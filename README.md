# folder-report

폴더 하나를 스캔해서 **파일 현황 요약 리포트(Markdown)** 를 만들어 주는 Rust CLI입니다.
"이 폴더에 뭐가 얼마나 들어 있지?", "용량은 누가 다 먹고 있지?", "최근에 뭘 건드렸지?"를
명령 한 줄로 확인할 수 있습니다.

- 대상 폴더의 파일은 **읽기만** 합니다 (수정·삭제·이동 없음).
- 단일 실행 파일, 설정 파일 없음. 의존성은 `chrono`(시간 표시용) 하나뿐입니다.
- 수십만 개 파일도 빠르게 처리합니다 (아래 [성능](#성능) 참고).

## 설치

필요한 것: [Rust](https://rustup.rs) (stable). 개발·테스트는 1.99에서 했고, 테스트 코드는 1.75 이상이 필요합니다.

**GitHub에서 바로 설치** (가장 간단)
```powershell
cargo install --git https://github.com/Hannoah/folder-report
```

**소스를 받아서 설치**
```powershell
git clone https://github.com/Hannoah/folder-report.git
cd folder-report
cargo install --path .
```

설치하면 `~\.cargo\bin\folder_report.exe`가 생기고, Rust 설치 시 이 경로가 PATH에 들어 있으므로
어느 폴더에서나 `folder_report`로 실행할 수 있습니다.

**설치 없이 빌드만 하려면**
```powershell
cargo build --release
.\target\release\folder_report.exe C:\Work
```

## 빠른 시작
```powershell
# 대상 폴더와 저장 위치, 이 두 개만 주면 됩니다
folder_report C:\Work D:\reports
# -> D:\reports\folder_report.md 에 저장됨
```

## 사용법
```
folder_report <대상폴더> [저장경로] [--top N] [--days N]
```

| 인자 | 설명 | 기본값 |
|---|---|---|
| `<대상폴더>` | 스캔할 폴더 (필수) | — |
| `[저장경로]` | 리포트를 저장할 위치 (선택). 두 번째 위치 인자 또는 `-o` / `--output` | 생략 시 화면에 출력 |
| `--top N` | "용량 상위" 와 "최근 수정" 표에 보여 줄 최대 개수 | `10` |
| `--days N` | "최근 수정"으로 볼 기간(일) | `7` |
| `-h`, `--help` | 도움말 | — |

**저장경로 규칙**
- 기존 **폴더**를 주면 그 안에 `folder_report.md`로 저장합니다.
- **파일 경로**를 주면 그 이름으로 저장합니다. 같은 이름의 파일이 있으면 **덮어씁니다.**
- 저장할 위치의 상위 폴더가 없으면 폴더를 만들지 않고 `오류: 저장 실패: ...`와 함께 종료 코드 `1`로 끝납니다.

### 예시
```powershell
folder_report C:\Work                              # 화면에 출력
folder_report C:\Work D:\reports                   # D:\reports\folder_report.md 로 저장
folder_report C:\Work D:\reports\work.md           # 파일명 지정
folder_report C:\Work work.md --top 20 --days 3    # 상위 20개, 최근 3일 기준
folder_report C:\Work -o work.md                   # -o 형태도 가능
```

## 리포트 내용
1. **요약:** 생성 시각, 총 파일 수, 총 용량
2. **확장자별 현황:** 확장자마다 파일 수와 용량 (용량 큰 순서). 확장자는 소문자로 합치며, 확장자가 없는 파일은 `(확장자 없음)`으로 묶입니다.
3. **용량 상위 N개 파일:** 대상 폴더 기준 상대 경로, 용량, 수정일
4. **최근 N일 내 수정된 파일:** 최근 수정 순서. N개를 넘으면 `외 M개 생략`으로 표시
5. **(조건부) 접근 불가 경고:** 권한 등으로 읽지 못한 항목이 있으면 요약 아래에 `⚠ 접근 불가로 건너뜀: N개`가 표시됩니다.

리포트는 항상 한국어로 출력됩니다.

## 출력 예시
```markdown
# 폴더 리포트: `C:\Work\demo_proj`

- 생성 시각: 2026-11-07 21:47:39
- 총 파일 수: 4개
- 총 용량: 4.2 MB

## 확장자별 현황

| 확장자 | 파일 수 | 용량 |
|---|---:|---:|
| .csv | 1 | 3.0 MB |
| .pdf | 1 | 1.2 MB |
| .md | 1 | 2.0 KB |
| (확장자 없음) | 1 | 512 B |

## 용량 상위 10개 파일

| 파일 | 용량 | 수정일 |
|---|---:|---|
| data/sales.csv | 3.0 MB | 2026-11-07 |
| docs/spec.pdf | 1.2 MB | 2026-10-18 |
| docs/notes.md | 2.0 KB | 2026-11-07 |
| README | 512 B | 2026-11-07 |

## 최근 7일 내 수정된 파일 (3개)

| 파일 | 수정 시각 |
|---|---|
| README | 2026-11-07 21:47 |
| docs/notes.md | 2026-11-07 21:47 |
| data/sales.csv | 2026-11-07 21:47 |
```
이 예시에서 `node_modules/` 안의 파일은 제외 대상이라 집계되지 않았습니다.

## 동작 방식과 주의점

**제외되는 폴더** (이름이 같은 폴더는 어느 깊이에 있든 통째로 건너뜀)
`.git`, `.venv`, `venv`, `__pycache__`, `node_modules`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`

> 이 때문에 개발 폴더에서는 탐색기에서 보는 파일 수보다 훨씬 적게 나올 수 있습니다
> (`node_modules`만 수십만 개인 경우가 흔합니다). Rust 프로젝트의 `target/`은 제외되지 **않습니다.**
> 제외 목록은 아직 옵션으로 바꿀 수 없고, `src/main.rs`의 `EXCLUDE_DIRS`를 수정해야 합니다.

**링크**
- 심볼릭 링크와 Windows 정션(junction) **폴더**는 따라가지 않습니다 (무한 순환 방지).
- 링크인 **파일**은 집계하지 않습니다 (링크 대상이 이중으로 잡히는 것 방지).

**출력 파일 자체**
- 저장 파일이 스캔 대상 폴더 안에 있어도 통계에서 제외됩니다. 같은 폴더에 반복 저장해도 파일 수가 늘어나지 않습니다.

**읽지 못한 항목**
- 권한이 없거나 오류가 난 폴더·파일은 건너뛰고 계속 진행하며, 건너뛴 개수를 리포트에 표시합니다.
  이 경우 총 파일 수와 용량은 **실제보다 작게** 집계된 값입니다.
- 어떤 항목을 건너뛰었는지 목록은 보여 주지 않고 개수만 보여 줍니다.

**기타**
- 시각은 이 PC의 로컬 시간대 기준이며, "수정일"은 파일의 최종 수정 시각(mtime)입니다.
- 용량 단위는 1024 기준(KB, MB, GB)입니다.
- 스캔 중에 파일이 바뀌면 그 시점의 값이 섞일 수 있습니다.
- 확장자는 파일 이름만 보고 판단합니다 (내용으로 종류를 추정하지 않음).
- 파일 이름에 `|`가 있으면 Markdown 표가 깨질 수 있습니다 (Windows에서는 해당 문자를 이름에 쓸 수 없어 실제로는 드뭅니다).

## 종료 코드
| 코드 | 의미 |
|---:|---|
| `0` | 성공 |
| `1` | 대상 폴더를 찾을 수 없음, 또는 리포트 저장 실패 |
| `2` | 잘못된 사용법 (인자 누락·과다, 알 수 없는 옵션, 숫자가 아닌 `--top`/`--days` 등) |

## 성능
Windows 11 PC에서 직접 측정한 값입니다 (환경에 따라 다릅니다).

| 대상 | 집계된 파일 | 시간 |
|---|---:|---:|
| 개발 데모 폴더 (제외 폴더 제외 후 10,056개) | 10,056 | 약 0.4초 (캐시 후) / 1.1초 (첫 실행) |
| 업무 폴더 전체 | 60,405 | 약 9초 |

같은 폴더를 이전에 Python으로 만든 버전으로 스캔했을 때보다 약 13~14배 빨랐습니다.

## 개발
```powershell
cargo test              # 단위/통합 테스트 (Windows에서는 정션 순환 테스트 포함)
cargo build --release   # 최적화 빌드 (LTO)
```

```
folder-report/
├── Cargo.toml
├── Cargo.lock
├── LICENSE
├── README.md
└── src/
    └── main.rs     # 스캔, 리포트 생성, CLI 인자 처리, 테스트
```

주요 함수: `scan`(폴더 순회) → `build_report`(Markdown 생성) → `run`(인자 처리, 저장).
리포트 형식을 바꾸려면 `build_report`만 보면 됩니다.

## 문제 해결
- **한글이 깨져서 보여요.** 화면 출력은 UTF-8입니다. 콘솔이 다른 코드 페이지면 `chcp 65001`을 먼저 실행하거나, 저장경로를 지정해 파일로 저장한 뒤 에디터로 여세요.
- **`folder_report`를 찾을 수 없다고 나와요.** 설치 후 터미널을 새로 열었는지 확인하고, `~\.cargo\bin`이 PATH에 있는지 확인하세요.
- **"폴더를 찾을 수 없습니다"가 나와요.** 경로에 공백이 있으면 따옴표로 감싸세요. 예: `folder_report "C:\My Work" D:\reports`
- **파일 수가 탐색기와 달라요.** 제외 폴더와 링크 파일 처리 때문입니다 ([동작 방식과 주의점](#동작-방식과-주의점) 참고). `접근 불가로 건너뜀` 경고가 있다면 권한 문제도 원인일 수 있습니다.
- **`오류: 저장 실패`가 나와요.** 저장할 위치의 상위 폴더가 없거나 쓰기 권한이 없는 경우입니다. 폴더를 먼저 만들어 주세요.
